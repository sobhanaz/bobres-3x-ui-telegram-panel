# نصب

[فهرست راهنما](FA-Home) · [قدم‌های اول](FA-First-Steps)

نصب BOBRES با یک دستور انجام می‌شود و حدود چند دقیقه طول می‌کشد. این صفحه می‌گوید پیش از نصب چه چیزهایی لازم است، نصب‌کننده چه می‌پرسد، چه کار می‌کند و اگر جایی گیر کرد چه باید کرد.

## پیش‌نیازها

**سرور**

- سیستم‌عامل: Ubuntu 22.04 یا 24.04، یا Debian 11، 12 یا 13.
- معماری: amd64 یا arm64.
- حافظهٔ RAM: دست‌کم ۱ گیگابایت (۲ گیگابایت پیشنهاد می‌شود). با ۱ گیگابایت نصب انجام می‌شود ولی هشدار می‌دهد.
- فضای خالی دیسک: دست‌کم ۱۰ گیگابایت.
- پورت‌های ۸۰ و ۴۴۳ آزاد باشند (Caddy برای HTTPS از آن‌ها استفاده می‌کند).
- دسترسی root.

**دامنه**

- یک دامنه یا زیردامنه، مثلاً `shop.example.com`، که رکورد A آن به نشانی IP همین سرور اشاره کند. گواهی HTTPS پس از اشاره کردن DNS صادر می‌شود. اگر نصب را زودتر از اشاره کردن DNS انجام دهید، نصب‌کننده فقط هشدار می‌دهد.

**تلگرام**

- یک ربات تازه از [@BotFather](https://t.me/BotFather): با دستور `/newbot` بسازید و توکن را نگه دارید. نام کاربری ربات باید به `bot` ختم شود، مثلاً `@my_vpn_bot`.
- **شناسهٔ عددی تلگرام** خودتان (مالک فروشگاه)، مثلاً `123456789`. شناسهٔ عددی را رباتی مثل @userinfobot نشان می‌دهد. نام کاربری (`@name`) به‌جای شناسهٔ عددی کافی نیست.

**پنل 3x-ui (اختیاری)**

- اگر از پیش پنل 3x-ui دارید (نسخه‌های v3.8.5 تا v3.10.2 آزموده شده‌اند)، نشانی آن و یک **توکن API** بخواهید. توکن را در خود 3x-ui، از Settings و بخش Security (API tokens) می‌سازید.
- اگر هنوز پنلی ندارید، همین مرحله را رد کنید. بعداً در داشبورد، در بخش «سرورهای پنل»، هر تعداد پنل 3x-ui یا Marzban اضافه می‌کنید.

## دستور نصب

با SSH به سرور وصل شوید. اگر root نیستید، اول `sudo -i` بزنید. بعد:

<div dir="ltr">

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sobhanaz/bobres-3x-ui-telegram-panel/main/install/install.sh)
```

</div>

اگر ترجیح می‌دهید همهٔ جواب‌های ساده را از خط فرمان بدهید (توکن‌ها هرگز نباید در خط فرمان بیایند، چون در تاریخچهٔ شل می‌مانند و نصب‌کننده آن‌ها را مخفی می‌پرسد):

<div dir="ltr">

```bash
curl -fsSL https://raw.githubusercontent.com/sobhanaz/bobres-3x-ui-telegram-panel/main/install/install.sh | sudo bash -s -- --domain shop.example.com --admin-id 123456789
```

</div>

فهرست همهٔ گزینه‌ها (پنل روی همین سرور، کپی پشتیبان‌ها در S3، زرین‌پال، پورت SSH دیگر، سخت‌سازی) را، وقتی نصب‌کننده یک بار دستور `bobres` را روی سرور گذاشت، این دستور نشان می‌دهد:

<div dir="ltr">

```bash
bobres install -h
```

</div>

## نصب‌کننده چه می‌پرسد؟

فقط چیزهایی را می‌پرسد که مقدار پیش‌فرض امن ندارند:

1. **دامنه**، مثلاً `shop.example.com`.
2. **شناسهٔ عددی تلگرام** مالک. اگر چند مالک دارید، شناسه‌ها را با ویرگول جدا کنید. اولی مالک اصلی است.
3. **توکن ربات** از BotFather. هنگام تایپ دیده نمی‌شود و پیش از ادامه با تلگرام سنجیده می‌شود.
4. **نشانی پنل 3x-ui** (اختیاری). با Enter رد می‌شود.
5. **توکن API پنل** (اگر نشانی دادید). این هم مخفی تایپ می‌شود و **پیش از نوشتن هر چیزی روی دیسک با پنل واقعی آزموده می‌شود**. اگر توکن را نپذیرد، پیام روشنی می‌دهد و چند بار دیگر می‌پرسد.

اگر پنل روی همین سرور است و نشانی آن `http://127.0.0.1:...` است، نیازی به تغییر نیست: نصب‌کننده خودش آن را به نشانی‌ای تبدیل می‌کند که کانتینرها بتوانند ببینند.

## نصب‌کننده چه می‌کند؟

1. **امضا را بررسی می‌کند.** برنامهٔ `bobres` را از آخرین انتشار GitHub می‌گیرد و پیش از اجرای هر چیزی، امضای Ed25519 و checksum آن را می‌سنجد.
2. **Docker را نصب می‌کند** (اگر نصب نیست).
3. **فروشگاه را بالا می‌آورد:** Caddy (HTTPS)، PostgreSQL، Redis و سرویس‌های BOBRES. صبر می‌کند تا همه سالم شوند.
4. **سرور را سخت‌سازی می‌کند**، هرجا ایمن باشد: فایروال (ufw)، fail2ban، به‌روزرسانی امنیتی خودکار و swap. با `--no-harden` می‌توانید این مرحله را رد کنید و بعداً با `sudo bobres harden` اجرا کنید.
5. در پایان کارت **«BOBRES is ready»** را چاپ می‌کند: نشانی فروشگاه، نام ربات، راه ورود به داشبورد، سلامت سرویس‌ها، وضعیت لایسنس و قدم‌های بعدی.

نوار پیشرفت از ۰ تا ۱۰۰ درصد دیده می‌شود. اگر خروجی یک فایل یا pipe باشد، به‌جای نوار، خط‌های ساده می‌نویسد.

> **کلید پشتیبان را همان لحظه ذخیره کنید.** نصب‌کننده یک بار «Backup key» را چاپ می‌کند. پشتیبان‌ها با این کلید رمزگذاری می‌شوند و بدون آن خوانده نمی‌شوند. آن را جایی دور از همین سرور نگه دارید (مثلاً در یک مدیر گذرواژه). اگر گم کردید و سرور هنوز هست، با دستور `sudo bobres` و گزینهٔ «Backup key» دوباره دیده می‌شود. کلید به تلگرام فرستاده نمی‌شود.

## لاگ نصب

هرچه برنامه‌های دیگر (apt، Docker) چاپ می‌کنند در فایل زیر می‌رود، نه روی صفحه:

<div dir="ltr">

```bash
tail -f /var/log/bobres-install.log
```

</div>

اگر اتصال SSH قطع شد، نصب پس از پاسخ دادن به سؤال‌ها ادامه می‌دهد. از یک نشست تازه همین دستور را بزنید تا ادامه را ببینید. اگر نصب واقعاً متوقف شده بود، دوباره اجرایش کنید: همهٔ تنظیم‌ها و رمزها نگه داشته می‌شوند و فقط کارهای ناتمام انجام می‌شود:

<div dir="ltr">

```bash
sudo bobres install
```

</div>

برای اینکه SSH کمتر قطع شود، با `ssh -o ServerAliveInterval=30 ...` وصل شوید.

## مشکل‌های رایج نصب

| پیام یا نشانه | معنی و راه‌حل |
|---|---|
| `unsupported OS` | سیستم‌عامل پشتیبانی نمی‌شود. فقط Ubuntu 22.04/24.04 و Debian 11/12/13 |
| `this installer must run as root` | با root یا با `sudo` اجرا کنید |
| RAM یا دیسک کم | زیر حدود ۹۰۰ مگابایت RAM یا زیر ۱۰ گیگابایت فضای خالی نصب انجام نمی‌شود. سرور بزرگ‌تری بگیرید |
| پورت ۸۰ یا ۴۴۳ پر است | برنامه‌ای مثل nginx یا Apache این پورت‌ها را گرفته. آن را متوقف کنید یا روی سرور دیگری نصب کنید |
| هشدار DNS | دامنه هنوز به این سرور اشاره نمی‌کند. رکورد A را درست کنید. گواهی HTTPS پس از اشاره کردن DNS صادر می‌شود |
| توکن ربات رد شد | توکن را دوباره از BotFather (`/mybots`، سپس API Token) بردارید و بدون فاصلهٔ اضافه بچسبانید |
| توکن پنل 3x-ui رد شد | در 3x-ui یک توکن API تازه بسازید. نشانی پنل باید مسیر پایه (web base path) را هم داشته باشد. با Enter می‌توانید پنل را رد کنید و بعداً در داشبورد اضافه کنید |
| نصب وسط کار قطع شد | `sudo bobres install` را دوباره بزنید و `/var/log/bobres-install.log` را بخوانید |

پس از نصب، این دو دستور وضعیت را نشان می‌دهند:

<div dir="ltr">

```bash
sudo bobres status
```

</div>

<div dir="ltr">

```bash
sudo bobres check
```

</div>
